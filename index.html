02

대표 사례

가장 손이 많이 갔고, 숫자로 확인된 작업입니다.

드로잉 시스템 레이어 관리 최적화

교육용 드로잉 게임 · (주)스윙크 · Cocos Creator, TypeScript · 설계 및 최적화 담당

문제

기존 드로잉 시스템은 사용자가 입력을 재개하거나 도구를 바꿀 때마다 새 레이어를 만들었습니다. 그리는 동안 레이어가 계속 쌓이면서 메모리와 렌더링 비용이 같이 올라갔고, 저사양 태블릿에서 특히 느려졌습니다.

해결

입력 이벤트와 도구 변경 이벤트를 분리했습니다. 도구를 바꿨다는 사실만으로는 레이어를 만들지 않고, 실제로 획이 시작되는 시점에만 만들도록 조건을 옮겼습니다. 

if (toolChanged && isDrawingStarted) {
    createNewLayer();
    toolChanged = false;
}

도구 변경 플래그를 그리기 시작 시점에 소비하도록 바꾼 부분.

결과

200개 → 40개평균 생성 레이어 수
약 80% 감소레이어 생성 호출 횟수

메모리와 렌더링 비용이 함께 줄었고, 문제가 됐던 저사양 태블릿에서 안정적으로 돌아갔습니다.

남은 생각

기능이 도는 것과 값싸게 도는 것은 다른 문제였습니다. 객체를 언제 만들지를 상태로 판단하게 바꿨더니 성능과 유지보수가 같이 좋아졌는데, 이후 작업에서도 같은 방식으로 먼저 의심해 보게 됐습니다.
